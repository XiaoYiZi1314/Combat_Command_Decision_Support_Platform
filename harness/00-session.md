# 00 · 会话工作流

任何改代码任务按此流程。跳步即违规。

## 1. 启动（门禁）

1. 完整阅读 [AGENTS.md](../AGENTS.md)。
2. 阅读 [README.md](README.md)。
3. 按任务类型阅读对应分册（见 README 第 4 节）。
4. 勾 [CHECKLIST.md](CHECKLIST.md)「修改前」。

未完成以上四步：禁止 Edit / Write / 破坏性 Bash。

## 2. 理解

- 先搜再写：用 Grep / Glob / Read 定位现有实现。
- 模仿仓库已有风格、库、包路径；不引入仓库未使用的框架。
- 确认落点：模块、分层、包名 `com.ccds.{模块}.{业务域}.{分层}`。

## 3. 实现

- 只做完成需求所需的最小改动。
- 风格与周围代码一致；公共 API 用中文 Javadoc。
- 不删文件、不改已发布 DDL、不改依赖文件（除非用户明确要求）。
- 遇到规范冲突：安全 > 架构 > 风格；禁止 > 强制 > 推荐。

## 4. 收尾

1. 能编译则验证编译。
2. 跑 CHECKLIST「修改后」与 [08-forbidden.md](08-forbidden.md)。
3. 向用户说明改了什么；**不自动 commit**。

## 5. 会话失效后重读

以下情况必须重新执行第 1 节：

- 上下文被压缩
- 新开 Agent 会话
- 启动子 Agent / 换人接手
- 任务从问答变成改代码
