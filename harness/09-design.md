# 09 · 设计原则

适用：新模块、接口设计、方案取舍。推荐规则；与强制/禁止冲突时以后者为准。

## 质量维度

可读性 > 可维护性 ≈ 可扩展性 > 复用性 ≈ 可测试性。

## 面向对象

封装、抽象、继承（强耦合，慎用）、多态。

- 面向接口，不面向实现。
- 多用组合，少用继承。
- 避免在类里堆过程式大段逻辑。
- 领域规则尽量放领域对象（充血）；Service 做编排与事务，避免全部贫血堆在 Service。

## SOLID

| 原则 | 要义 |
|------|------|
| SRP | 一个类一件事 |
| OCP | 扩展开放、修改关闭 |
| LSP | 子类可替换父类 |
| ISP | 接口按调用方拆小 |
| DIP | 依赖抽象，不依赖细节 |

## 其他

- **DRY**：消灭语义重复，不是机械去重每一行。
- **KISS**：简单优先；不为微性能牺牲可读；不造轮子；不用同事看不懂的技巧。
- **YAGNI**：不做当前不需要的功能；可留扩展点，不提前加依赖。
- **LOD**：不该依赖的类不要依赖；该依赖的只依赖必要接口。
