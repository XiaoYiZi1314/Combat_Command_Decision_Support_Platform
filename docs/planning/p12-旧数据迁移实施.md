# CCDS 旧数据迁移实施（v1.0，已实跑验证）

- **目的**：把客户旧版 APP（作战指挥辅助决策平台 7.84 / 8.76，源码见 `nxgk_6241_source`）留下的业务数据迁移到本仓库 CCDS 表结构，作为 [p11-需求更新方案](p11-需求更新方案.md) 的数据底座。
- **数据来源**：① 旧版 APK 内置资源 `tmp_apk/extracted/assets/`；② 客户旧系统的 Cloudflare R2 桶 `nxgk-files`（凭证在旧版 `assets/cloud_config.js`，**未入库**）。
- **验证方式**：不只生成脚本。本机起了**独立 MySQL 8.0.46 实例（端口 3307，数据目录在 `%TEMP%`，不碰现有库）**，按 `0001…0009` 顺序建库 → 应用迁移 SQL → 用**重新打包的 Spring Boot jar + 真实 NDJSON** 跑导入器 → 核对条数、幂等、失败项。下文所有数字都是**实跑结果**，不是估算。

## 八、执行手册

```powershell
# 0) 前置：Node ≥ 20；后端有 MySQL 8 + Redis；CCDS_FIELD_SECRET 已配置
# 1) 抽内置种子与水源
node ccds-bootstrap/scripts/migration/extract-bundle-core.mjs
node ccds-bootstrap/scripts/migration/extract-bundle-water.mjs
node ccds-bootstrap/scripts/migration/build-water-sql.mjs
# 2) 抽云端花名册（约 1~2 分钟，只读）
node ccds-bootstrap/scripts/migration/extract-cloud.mjs
# 3) 附件盘点（默认不下载；按需加 --download=water_doc,drain,ins / keyunit / all）
node ccds-bootstrap/scripts/migration/build-file-manifest.mjs --download=water_doc,drain,ins
# 4) 建表与灌数（顺序不可换）
mysql> source 0009_legacy_seed/0000_landing_tables.sql
mysql> source 0009_legacy_seed/0002_water_fields.sql
mysql> source 0009_legacy_seed/0001_water_source.sql
# 5) 干跑 → 真实导入
$env:CCDS_LEGACY_DATA_DIR="$env:TEMP\ccds-migration"; $env:CCDS_LEGACY_DRY_RUN="1"
java -jar ccds-bootstrap/target/ccds-bootstrap-*.jar      # 看汇总数字是否符合预期
$env:CCDS_LEGACY_DRY_RUN="0"; java -jar ...               # 真实写库
# 6) 附件登记（需 COS 凭证）
$env:CCDS_LEGACY_IMPORT_MANIFEST="$env:TEMP\ccds-migration\legacy-file-manifest.json"
java -jar ...                                             # LegacyObjectImportRunner 上传 COS + 登记 file_object
# 7) 核对
mysql> source 0009_legacy_seed/verify.sql
mysql> source 0009_legacy_seed/verify_water.sql
```

**回滚**：`0000/0002` 只新增表与列（`DROP TABLE ccds_profile_tombstone/ccds_station_scba_setting/ccds_station_work_mode`、`ALTER TABLE ccds_water_source DROP COLUMN …`）；`0001` 只插入本次新增行（按 `extra_json IS NULL AND gmt_create = <迁移日>` 或 `(station_id,name)` 名单删除）；Java 导入按唯一键可重复执行，删除导入行即可复原。**不要**用 `TRUNCATE`（会连带清掉既有种子数据）。

## 十一、风险与安全

| 风险 | 现状 | 处置 |
|---|---|---|
| R2 凭证落在旧版 `cloud_config.js` | 该文件在 `tmp_apk/`，已被 `.gitignore` 排除；工具只在运行时读取 | **不要**把凭证写进代码/文档/清单；迁移完成后建议客户轮换 R2 密钥并关闭公共读 |
| 明文电话 | NDJSON 内存流转，SQL 不落明文；库内 `v1:` AES-GCM | 迁移机磁盘上的 `roster.ndjson` 属敏感文件，用完即删；`CCDS_FIELD_SECRET` 不得与 NDJSON 同机长期留存 |
| 精确坐标 | 643 条水源坐标入 `lng/lat`（沿用一期现状） | 导出/接口按角色控制；日志不打印坐标 |
| 附件体积 | 预案 3.3 GB + 视频 3.7 GB | 默认不下载；`--download` 分批 + `--limit` 抽测；只迁业务必需 |
| 旧数据脏值 | 见 §七 | 迁移期原样保留 + 清单交现场；不在脚本里"猜"正确值 |
| 重跑覆盖 | 全部按唯一键 upsert / NOT EXISTS | 已验证幂等；禁止 `TRUNCATE` / `REPLACE INTO` |
